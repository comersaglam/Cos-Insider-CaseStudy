## Goal

GitHub Actions that lint, test and build every push, and publish the image on a release, as the brief's CI/CD bonus
asks.

## Steps

1. Asked the owner, who chose publishing to `ghcr.io` on a `v*` tag only, and every action pinned to a commit SHA
   with Dependabot.
2. Resolved each action's latest release tag to its commit, dereferencing annotated tags, and checked the commit
   exists; read each action's inputs at that commit.
3. Wrote `.github/workflows/ci.yml` (lint, test, image; publish on a tag, the only job that may write packages)
   and `.github/dependabot.yml` (Go modules, actions, the Dockerfile's images; weekly and grouped).
4. Ran what the jobs run: `make test`, the whole suite at once as CI runs it, green in 41 s; golangci-lint 2.15.0.
5. The roadmap also planned `govulncheck` and a check of the generated query code. Added `make verify`
   (`go mod tidy -diff`, `sqlc diff`, `govulncheck` at a pinned version) to `make check` and to the lint job, with
   sqlc run through `go run` in CI.
6. A surprise: `govulncheck`'s first run found GO-2026-6865 in `klauspost/compress` 1.20.1, reached through
   Prometheus's handler, and then GO-2026-6974 in OpenTelemetry 1.44.0, reached through testcontainers in tests
   only. Moved them to 1.20.2 (a patch) and 1.47.0 (a minor release, which also moved `go-logr/logr` to 1.4.4),
   the fixed releases; no new dependency, the whole suite passed again and the scan is clean.

## Verification

- `make verify`, as locally and as CI runs it (sqlc through `go run`), passes.
- `make test` green with every package; `golangci-lint` 0 issues.
- Both YAML files parse; all 13 `uses:` name a full SHA with its version beside it.
- The workflow itself runs only once the repository is pushed, which is the owner's call.
